# 02. Thread, 문맥 교환과 동시성

## 대표 면접 질문

> **Q. Process의 Thread들은 무엇을 공유하며, CPU는 여러 Thread를 어떻게 실행하나요?**

**30초 답변:** 같은 Process의 Thread들은 주소 공간과 파일 등의 자원을 공유하고 각자 실행 위치·레지스터 상태·Stack을 가집니다. 운영체제는 문맥 교환으로 실행 대상을 바꿔 한 코어에서도 여러 작업을 진행할 수 있습니다. 서로 다른 코어에서 같은 순간 실행되는 것은 병렬성입니다.

**핵심 키워드:** Thread · 공유 주소 공간 · 문맥 교환 · 스케줄링 · 동시성 · 병렬성

## Process와 Thread

### 핵심 개념

- **Process:** 실행 중인 프로그램. 운영체제가 주소 공간·파일 등 자원을 관리하는 단위.
- **Thread:** Process 안에서 명령을 실행하는 흐름. Process에는 Thread가 하나 이상 있음.
- **공유:** 같은 Process의 Thread들은 주소 공간과 열린 파일 등 Process 자원에 접근할 수 있음.
- **독립:** Thread마다 실행 위치·레지스터 상태·Stack이 따로 있음.
- **동기화:** 공유 데이터를 동시에 수정할 때 결과가 꼬이지 않도록 조정하는 것.
- **IPC:** 서로 다른 Process가 데이터를 주고받는 방법. 파이프·소켓·공유 메모리 등.

| 구분 | Process | Thread |
| --- | --- | --- |
| 중심 역할 | 자원 관리 | 명령 실행 |
| 메모리 | 다른 Process와 주소 공간이 구분됨 | 같은 Process의 주소 공간 공유 |
| 실행 상태 | 하나 이상의 Thread를 포함 | 자기 실행 위치와 Stack을 가짐 |

> **한 문장:** Process는 **실행 환경**, Thread는 그 안의 **실행 흐름**.

### 짧은 Java 예제

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            // worker Thread가 맡은 작업
            System.out.println("파일 처리");
        });

        worker.start(); // 새 실행 흐름 시작
        System.out.println("화면 처리"); // main Thread의 작업
        worker.join(); // worker 종료 대기
    }
}
```

프로그램 실행 한 번은 **Process 하나**의 예입니다. `main`과 `worker`는 그 안의 **서로 다른 Thread**입니다. 두 출력의 순서는 일정하지 않습니다.


## 문맥 교환

운영체제는 CPU에서 실행할 Thread를 바꿀 때 현재 실행 상태를 저장하고 다음 Thread의 상태를 복원합니다.

### 핵심 단어

| 단어 | 의미 |
| --- | --- |
| **스케줄러** | 다음에 실행할 Thread를 선택 |
| **문맥(Context)** | 실행 위치, 레지스터 값 등 이어서 실행하는 데 필요한 상태 |
| **문맥 저장·복원** | 현재 상태를 보관하고 다음 Thread의 상태를 불러옴 |
| **교환 비용** | 상태를 바꾸는 동안 작업 자체는 진행되지 않음 |

**Thread A 실행 → A의 상태 저장 → B의 상태 복원 → Thread B 실행**

CPU 사용 시간이 지나거나 Thread가 대기 상태로 들어갈 때 다른 Thread로 전환될 수 있습니다. 실제 전환 시점은 운영체제 스케줄링에 따라 달라집니다.

### 짧은 Java 예제

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> {
            for (int i = 0; i < 3; i++) {
                // 현재 실행 중인 Thread의 이름을 출력
                System.out.println(Thread.currentThread().getName() + ": " + i);
            }
        };

        Thread a = new Thread(task, "A");
        Thread b = new Thread(task, "B");

        a.start(); // 두 Thread를 실행 가능하게 만듦
        b.start();
        a.join();  // 종료할 때까지 대기
        b.join();
    }
}
```

A와 B의 출력 순서는 보장되지 않습니다. **출력 순서만으로 실제 문맥 교환 횟수를 알 수는 없습니다.**


## 동시성과 병렬성

### 개념

| 구분 | 동시성 | 병렬성 |
| --- | --- | --- |
| 관찰 | 여러 작업이 진행 | 여러 작업이 같은 순간 실행 |
| 코어 하나 | 번갈아 실행 가능 | 같은 순간 두 CPU 작업 실행 불가 |
| 여러 코어 | 가능 | 서로 다른 코어에서 가능 |

코어 하나가 A와 B를 번갈아 실행해도 두 작업은 **동시적**으로 진행됩니다. 코어가 여럿이면 A와 B가 실제로 **병렬** 실행될 수 있습니다. 병렬 실행도 여러 작업이 함께 진행한다는 의미에서는 동시성에 포함됩니다.

### Java 예제

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread a = new Thread(() -> work("A"));
        Thread b = new Thread(() -> work("B"));

        a.start(); // 두 작업을 실행 가능하게 만든다.
        b.start();
        a.join();  // 두 작업이 끝날 때까지 기다린다.
        b.join();
    }

    static void work(String name) {
        for (int i = 0; i < 3; i++) {
            // 출력 순서는 실행 환경에 따라 달라질 수 있다.
            System.out.println(name + ": " + i);
        }
    }
}
```

두 Thread의 작업은 겹쳐 진행할 수 있지만, 이 출력만으로 두 코어에서 실제 병렬로 실행됐는지는 판단할 수 없습니다.


## 핵심 정리

- Process는 자원을 관리하고 Thread는 명령을 실행합니다.
- 문맥 교환은 Thread의 실행 상태를 저장하고 복원하며 비용이 듭니다.
- 동시성은 함께 진행되는 성질이고 병렬성은 같은 순간에 실제로 실행되는 성질입니다.
- 여러 Thread를 만들었다고 병렬 실행이나 성능 향상이 보장되지는 않습니다.

## 꼬리 질문과 답

- 같은 Process의 Thread 사이에도 문맥 교환이 있나요? 네.
- 출력 순서로 실제 문맥 교환 횟수를 알 수 있나요? 아니요.
- 코어 하나에서 동시성이 가능한가요? 네. 실행 대상을 교체할 수 있습니다.
