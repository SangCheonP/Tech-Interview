# 01. Program, Process와 메모리

## 대표 면접 질문

> **Q. 프로그램을 실행하면 운영체제는 어떤 Process와 메모리 공간을 만들까요?**

**30초 답변:** 프로그램은 실행할 코드이고 Process는 운영체제가 관리하는 실행 단위입니다. 같은 프로그램을 두 번 실행하면 일반적으로 PID와 가상 주소 공간이 각각 생깁니다. Process에는 코드, 데이터, 동적 할당 영역, Thread별 Stack 등이 있으며 JVM도 이 공간 안에서 동작합니다.

**핵심 키워드:** 실행 파일 · PID · 가상 주소 공간 · 코드/데이터 · Heap · Stack

## 프로그램과 Process

### 개념

**Program**은 실행할 코드가 담긴 파일이고, **Process**는 프로그램이 실행되어 운영체제가 관리하는 실행 단위입니다. 같은 프로그램을 두 번 실행하면 일반적으로 별개의 Process 두 개가 생깁니다. Process에는 PID, 가상 주소 공간, 열린 파일 등의 자원이 있고, 코드를 실제로 실행하는 Thread가 하나 이상 있습니다.

| 구분 | Java 예시 |
| --- | --- |
| Program | 실행을 위해 준비된 클래스 파일과 필요한 라이브러리 |
| Process | `java Main`으로 실행 중인 JVM |
| PID | 운영체제가 Process를 구분하는 번호 |

### 직접 확인해 보기

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        // 현재 Java 프로그램을 실행 중인 Process의 PID를 출력한다.
        System.out.println("PID: " + ProcessHandle.current().pid());

        // PID를 확인할 수 있도록 30초간 프로그램을 종료하지 않는다.
        Thread.sleep(30_000);
    }
}
```

컴파일한 뒤 터미널 두 개에서 각각 `java Main`을 실행해 보세요. 서로 다른 PID가 출력됩니다. `ProcessHandle.current()`는 현재 Process를 나타내고, `pid()`로 식별 번호를 확인할 수 있습니다.

### JVM과의 관계

두 터미널에서 실행한 Java 프로그램은 각각 별도의 JVM Process입니다. 따라서 각 JVM의 Heap도 별도로 관리됩니다. 한쪽의 지역 변수나 Heap 객체를 다른 쪽에서 일반 Java 참조만으로 직접 읽을 수는 없습니다.

반면 하나의 Process 안에서는 여러 Thread가 같은 Heap의 객체에 접근할 수 있습니다. 앞에서 배운 **Thread별 Stack, 공유 Heap**은 *같은 JVM Process 안의 Thread들*에 관한 설명입니다.

## Process의 가상 주소 공간

Process는 자신이 사용할 가상 주소 공간을 가집니다. 운영체제가 가상 주소를 실제 메모리와 연결해 관리하며, Process마다 주소 공간이 구분됩니다. 다음은 전통적인 Process 메모리 구조를 설명하는 **개념적 분류**입니다. 실제 배치와 할당 방식은 운영체제와 실행 환경에 따라 달라집니다.

| 영역 | 주로 담는 것 |
| --- | --- |
| 코드(Text) | 실행할 기계어 명령 |
| 데이터(Data·BSS) | 전역·정적 데이터 등 |
| Heap | 실행 중 동적으로 확보하는 메모리 |
| Stack | Thread의 함수 호출에 필요한 정보 |
| 메모리 매핑 | 공유 라이브러리, 매핑된 파일 등 |

### JVM은 어디에 있을까?

`java Main`을 실행하면 운영체제는 **Java Process**를 관리하고, 그 안에서 **JVM**이 동작합니다. JVM은 Process의 가상 메모리를 사용하면서 Java 프로그램을 위한 Runtime Data Area를 관리합니다.

| 관점 | Heap·Stack을 설명하는 의미 |
| --- | --- |
| 운영체제의 Process | Process의 가상 메모리와 Thread의 실행을 설명하는 구분 |
| JVM | Java 객체를 할당하는 JVM Heap과 Thread별 메서드 호출 프레임을 관리하는 JVM Stack |

**메모리가 두 벌 있다는 뜻은 아닙니다.** JVM도 운영체제가 제공하는 Process 메모리에서 동작합니다. 그러나 이름이 같다고 `OS Heap = JVM Heap`, `OS Stack = JVM Stack`처럼 일대일로 대응시키면 부정확합니다. Java의 `static` 필드 역시 OS의 Data·BSS 영역에 반드시 놓인다고 단정할 수 없습니다. JVM은 클래스별 필드·메서드 정보 등을 자체 실행 영역에서 관리합니다.

### Java 코드로 연결하기

```java
public class Main {
    static class User {
        int age = 25; // User 객체가 가지는 필드
    }

    static void work() {
        int count = 1;          // 호출 프레임의 지역 변수
        User user = new User(); // User 객체는 JVM Heap의 할당 대상
        System.out.println(count + user.age);
    }

    public static void main(String[] args) {
        work(); // main Thread가 work()를 호출
    }
}
```

`work()`를 호출하면 실행 중인 Thread의 **JVM Stack에 프레임**이 만들어집니다. `count`와 `user` 참조는 이 메서드의 지역 변수로 이해할 수 있고, `new User()`로 만든 **객체 자체는 JVM Heap의 할당 대상**입니다. 메서드가 끝나면 해당 호출의 프레임도 사라집니다. 실제 물리적 배치는 JVM 최적화에 따라 달라질 수 있습니다.

### 두 관점의 연결

같은 `java Main`을 두 번 실행하면 일반적으로 서로 다른 JVM Process와 가상 주소 공간이 생깁니다. 따라서 한쪽의 Java 참조로 다른 쪽의 객체를 바로 사용할 수 없습니다. 반면 **하나의 JVM Process 안의 Thread들**은 같은 JVM Heap의 객체에 접근할 수 있고, 각자의 JVM Stack을 사용합니다. 이 차이가 다음 문서의 Thread와 동시성의 출발점입니다.

## 핵심 정리

- 프로그램은 실행할 코드, Process는 운영체제가 관리하는 실행 환경입니다.
- Process는 각각 가상 주소 공간을 가지고 Thread가 실제 명령을 실행합니다.
- JVM Heap과 Stack은 Process 메모리를 사용하지만 OS의 이름이 같은 영역과 일대일로 대응하지 않습니다.

## 꼬리 질문과 답

- 같은 프로그램을 두 번 실행하면? 보통 서로 다른 PID와 주소 공간의 Process 두 개가 생깁니다.
- 가상 주소가 물리 RAM 주소와 같나요? 아닙니다. 운영체제가 가상 주소를 물리 메모리에 매핑합니다.
- Java `static` 필드를 OS Data 영역에 반드시 놓을 수 있나요? 아닙니다. JVM 구현에 따라 관리됩니다.
