# 04. Context Switching

**Context Switching(문맥 교환)**은 CPU에서 실행할 Thread가 바뀔 때, 기존 Thread의 실행 상태를 저장하고 다음 Thread의 상태를 복원하는 과정입니다.

## 핵심 단어

| 단어 | 의미 |
| --- | --- |
| **스케줄러** | 다음에 실행할 Thread를 선택 |
| **문맥(Context)** | 실행 위치, 레지스터 값 등 이어서 실행하는 데 필요한 상태 |
| **문맥 저장·복원** | 현재 상태를 보관하고 다음 Thread의 상태를 불러옴 |
| **교환 비용** | 상태를 바꾸는 동안 작업 자체는 진행되지 않음 |

**Thread A 실행 → A의 상태 저장 → B의 상태 복원 → Thread B 실행**

CPU 사용 시간이 지나거나 Thread가 대기 상태로 들어갈 때 다른 Thread로 전환될 수 있습니다. 실제 전환 시점은 운영체제 스케줄링에 따라 달라집니다.

## 짧은 Java 예제

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> {
            for (int i = 0; i < 3; i++) {
                // 현재 실행 중인 Thread의 이름을 출력
                System.out.println(Thread.currentThread().getName() + ": " + i);
            }
        };

        Thread a = new Thread(task, "A");
        Thread b = new Thread(task, "B");

        a.start(); // 두 Thread를 실행 가능하게 만듦
        b.start();
        a.join();  // 종료할 때까지 대기
        b.join();
    }
}
```

A와 B의 출력 순서는 보장되지 않습니다. **출력 순서만으로 실제 문맥 교환 횟수를 알 수는 없습니다.**

## 앞선 주제와 연결

03번에서 Thread마다 **독립적인 실행 상태**가 있다고 배웠습니다. 그 상태를 저장하고 복원하기 때문에 CPU가 다른 Thread를 실행한 후에도 이전 작업을 이어갈 수 있습니다.

## 면접 답변

> Context Switching은 CPU에서 실행할 Thread가 바뀔 때 기존 Thread의 실행 상태를 저장하고 다음 Thread의 상태를 복원하는 과정입니다. 운영체제 스케줄러가 실행 대상을 선택하며, 상태를 전환하는 데 추가 비용이 듭니다.

**핵심 요약:** **스케줄러가 선택 → 현재 상태 저장 → 다음 상태 복원 → 실행 재개.**
