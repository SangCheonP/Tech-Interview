# 면접 학습 문서 작성 기준

[Interview_Question_for_Beginner](https://github.com/jbee37142/Interview_Question_for_Beginner)의 **분야별 질문 목록**을 학습 범위의 기준으로 참고합니다. 각 질문의 답은 공식 문서와 현재 구현을 확인해 직접 작성합니다. 기존 저장소의 문장을 복사하지 않고, Java 웹 개발 면접에서 설명할 수 있도록 내용을 연결합니다.

## 문서 단위와 읽기 흐름

- 하나의 면접 질문마다 파일을 만들지 않습니다. 함께 설명해야 이해되는 개념은 한 문서 안의 소제목으로 묶습니다.
- 예: 객체 생성과 GC, Process와 가상 메모리, Thread와 문맥 교환·동시성.
- 실제 본문이 준비된 파일만 목차에서 연결하고, 각 학습 문서 맨 아래에는 다음 문서로 이동하는 링크를 둡니다. 다음 문서가 아직 없다면 해당 분야의 목차로 연결합니다.

## 한 주제의 기본 흐름

1. **대표 면접 질문:** 한 문장으로 답할 수 있는 중심 질문을 맨 위에 둡니다.
2. **30초 답변:** 정의 → 작동 원리 또는 차이 → 주의점을 2~4문장으로 답합니다.
3. **핵심 키워드:** 면접 직전 빠르게 복습할 단어만 적습니다.
4. **개념과 예제:** 근거, 짧은 Java 코드와 한국어 주석, 필요할 때 작은 표를 제공합니다.
5. **앞선 주제와 연결:** 이전 개념이 이번 주제에 어떻게 쓰이는지 설명합니다.
6. **꼬리 질문과 답:** 빈번한 혼동과 예외를 짧게 확인합니다.
7. **핵심 정리와 참고 자료:** 한두 문장으로 마무리하고 신뢰할 수 있는 문서를 연결합니다.

## 정확성과 화면 기준

- **명세와 구현 구분:** JVM 명세의 규칙과 HotSpot 같은 구현의 동작을 구분합니다.
- **보장과 가능성 구분:** 스케줄링, GC 시점, JIT 적용을 확정적으로 쓰지 않습니다.
- **OS와 JVM 관점 구분:** Process의 가상 메모리와 JVM Runtime Data Area를 같은 이름만으로 일대일 대응하지 않습니다.
- **모바일 가독성:** 큰 ASCII 도식 대신 2~3열 표나 작은 Mermaid 그림을 사용합니다. 박스 글자는 짧게 쓰고 줄바꿈을 명확히 합니다.
- **학습과 게시 분리:** 설명한 주제를 사용자가 검토한 뒤 요청할 때만 GitHub 문서로 반영합니다.
