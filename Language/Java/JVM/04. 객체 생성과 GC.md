# 04. 객체 생성과 GC

## 대표 면접 질문

> **Q. 객체가 생성되어 사용되다가 GC의 회수 대상이 되기까지 어떤 일이 일어나나요?**

**30초 답변:** 필요한 클래스가 준비된 뒤 `new`로 객체가 할당되고 생성자가 실행됩니다. 참조를 통해 객체를 사용하는 동안에는 접근 가능하며, GC Root에서 더 이상 도달할 수 없으면 회수 대상이 됩니다. 메서드 종료나 `null` 대입이 즉시 삭제를 뜻하지는 않습니다.

**핵심 키워드:** 객체 할당 · 생성자 · 지역 참조 · GC Root · 도달 가능성 · 회수 시점

## 객체 생성과 참조

### 1. `new`로 객체를 만들면?

```java
class User {
    String name;
    int age;

    User(String name, int age) {
        // 생성된 객체의 필드에 값을 저장한다.
        this.name = name;
        this.age = age;
    }
}

public void createUser() {
    // 지역 변수 user가 새 User 객체를 참조한다.
    User user = new User("상천", 24);
}
```

개념적인 순서는 다음과 같습니다.

1. `createUser()` 호출에 따라 해당 메서드의 Stack Frame이 만들어집니다.
2. `new User(...)`로 Heap에 `User` 객체를 위한 공간이 할당됩니다.
3. 생성자가 실행되면서 객체의 `name`, `age` 필드를 초기화합니다.
4. 지역 변수 `user`에 생성된 객체를 가리키는 참조가 저장됩니다.

실제로는 객체를 만들기 전에 필요한 클래스가 로딩·초기화되는 과정 등이 있을 수 있습니다. 위 순서는 Stack과 Heap의 관계를 이해하기 위한 단순화입니다.

| 위치 | 저장되는 것 |
| --- | --- |
| `createUser()`의 Stack Frame | 지역 변수 `user`의 참조 |
| Heap의 `User` 객체 | `name`, `age` 필드의 값 |

`user`라는 지역 변수에 객체 전체가 들어가는 것은 아닙니다. `user`를 통해 Heap의 객체에 접근합니다.

### 2. 참조를 복사하면 객체도 복사될까?

```java
User first = new User("상천", 24);
User second = first;

// 두 변수가 같은 객체를 가리키므로 first로 읽어도 변경된 값이 보인다.
second.age = 25;
System.out.println(first.age); // 25
```

`second = first`는 참조를 대입합니다. 새 `User` 객체를 만들지 않으므로 두 지역 변수는 **같은 객체**를 가리킵니다.

반면 `new`를 각각 실행하면 필드 값이 같더라도 서로 다른 객체가 생성됩니다.

```java
User first = new User("상천", 24);
User second = new User("상천", 24);

// 참조형 변수의 ==는 두 변수가 같은 객체를 가리키는지 비교한다.
System.out.println(first == second); // false
```

### 3. 메서드가 끝나면 객체도 사라질까?

```java
public void createUser() {
    User user = new User("상천", 24);
} // 메서드가 끝나면 이 호출의 Stack Frame이 제거된다.
```

메서드 종료로 지역 변수 `user`는 사라지지만, Heap의 객체가 그 순간 즉시 삭제되지는 않습니다. **다른 곳에서도 객체에 접근할 수 없다면** GC의 회수 대상이 될 수 있습니다.

객체의 참조를 반환하면 호출자가 계속 접근할 수 있습니다.

```java
public User createUser() {
    // 객체 자체를 복사하는 대신 객체의 참조를 반환한다.
    return new User("상천", 24);
}

User user = createUser(); // 호출자의 지역 변수가 반환된 객체를 참조한다.
```

| 상황 | 메서드 종료 후 객체 |
| --- | --- |
| 다른 곳에서 접근 가능한 참조가 없음 | GC 대상이 될 수 있음 |
| 반환값이나 다른 객체의 필드 등을 통해 접근 가능 | 계속 사용할 수 있음 |

GC의 회수 시점과 원리는 아래에서 이어서 설명합니다.

### 4. 객체 안에 다른 객체가 있으면?

```java
class Team {
    User leader;
}

User user = new User("상천", 24);
Team team = new Team();
team.leader = user; // Team 객체의 필드가 User 객체를 참조한다.
```

`user`와 `team`이 메서드의 지역 변수라면 두 변수는 Stack Frame에 있습니다. `User`와 `Team` 객체는 Heap에 있으며, `leader`는 **Heap의 Team 객체에 속한 필드**입니다.

| 요소 | 개념적인 위치 |
| --- | --- |
| 지역 변수 `user`, `team` | 현재 메서드의 Stack Frame |
| `User`, `Team` 객체 | Heap |
| `Team` 객체의 `leader` 필드 | Heap에 있는 `Team` 객체 내부 |

따라서 **“모든 참조 변수는 Stack에 있다”**고 외우면 안 됩니다. 지역 변수로 선언된 참조와 객체의 필드로 저장된 참조는 위치가 다릅니다.

## GC와 객체의 수명

### 1. GC란?

Java에서는 일반 객체의 Heap 메모리를 직접 해제하지 않습니다. GC는 더 이상 도달할 수 없는 객체의 메모리를 재사용할 수 있게 합니다. 회수 대상이 된 시점과 실제 회수 시점은 다를 수 있습니다.

### 2. GC Root와 도달 가능성

**GC Root는 객체 참조 관계를 탐색할 때 기준이 되는 시작점**입니다. JVM은 Root에서 참조를 따라가며 도달 가능한 객체를 확인합니다.

- 도달 가능: 계속 사용할 수 있는 객체
- 도달 불가능: 회수 대상이 될 수 있는 객체

대표적인 시작점에는 실행 중인 메서드에서 사용 가능한 **참조형 지역 변수**, 살아 있는 클래스의 **static 참조**, JVM이 보유한 참조 등이 있습니다. `int age = 25`처럼 기본형 값은 객체를 가리키는 참조가 아닙니다. 또 지역 변수가 선언되었다고 해서 메서드 끝까지 반드시 Root로 유지되는 것은 아닙니다. JVM의 최적화와 이후 사용 여부에 따라 객체가 더 일찍 도달 불가능해질 수도 있습니다.

```java
User user = new User("상천", 24); // 사용 가능한 지역 참조에서 User 객체에 도달
Team team = new Team();
team.leader = user;              // Team 객체를 통해서도 User 객체에 도달
```

`user` 참조가 사라져도 `team`에 접근할 수 있고 `team.leader`가 객체를 가리키면 `User` 객체는 계속 도달 가능합니다. 핵심은 **객체까지 이어지는 참조 경로가 있는가**입니다.

### 3. 참조를 끊으면 즉시 삭제될까?

```java
User first = new User("상천", 24);
User second = first;

first = null; // first의 참조만 끊는다.
System.out.println(second.name); // second를 통해 같은 객체에 접근할 수 있다.
```

`first = null`은 이 변수의 참조를 끊을 뿐입니다. 다른 참조가 있으면 객체는 계속 사용됩니다. 다른 참조가 없어져도 그 자리에서 즉시 회수된다고 보장되지는 않습니다.

서로를 참조하는 두 객체도 Root에서 어느 쪽에도 도달할 수 없다면 함께 회수 대상이 될 수 있습니다. GC를 단순한 **참조 개수 세기**로 이해하면 안 되는 이유입니다.

### 4. GC가 있는데도 메모리가 부족한 이유

```java
List<User> users = new ArrayList<>();

while (true) {
    // 리스트가 모든 User 객체의 참조를 계속 보관한다.
    users.add(new User("상천", 24));
}
```

`users`를 통해 객체에 계속 도달할 수 있다면 GC는 그 객체들의 메모리를 함부로 회수할 수 없습니다. 필요 없는 참조를 컬렉션 등에 오래 보관하면 Heap 사용량이 커지고, 공간을 확보하지 못할 때 `OutOfMemoryError: Java heap space`가 발생할 수 있습니다.

### 5. GC와 프로그램 일시 정지

GC 방식에 따라 애플리케이션 작업을 잠시 멈추는 구간이 있을 수 있습니다. 수집기와 단계에 따라 일부 작업을 애플리케이션과 동시에 수행하기도 합니다. 지금은 **자동 메모리 관리에도 실행 비용이 든다**는 점을 기억하면 충분합니다.

## 핵심 정리

- `new`는 객체를 만들며 참조 대입만으로는 객체가 복사되지 않습니다.
- 지역 참조는 메서드 호출의 프레임에, 객체의 참조형 필드는 그 객체에 속합니다.
- GC는 Root에서 객체까지 참조 경로가 있는지를 기준으로 회수 대상을 판단합니다.
- 객체에 도달할 수 없어도 즉시 회수된다는 보장은 없습니다.
- 불필요한 참조를 오래 보관하면 GC가 있어도 Heap이 부족해질 수 있습니다.

## 꼬리 질문과 답

- `second = first`는 새 객체를 만들까요? 아니요. 같은 객체를 가리키는 참조가 복사됩니다.
- 모든 지역 변수가 GC Root인가요? 아니요. 기본형 값은 참조가 아니고, 참조도 이후 사용 여부와 최적화에 따라 유효 범위가 달라집니다.
- 서로를 참조하는 객체는 회수되지 않나요? Root에서 도달할 수 없다면 함께 회수 대상이 됩니다.
