# Class Loader

Java 소스를 컴파일하면 Bytecode가 담긴 `.class` 파일이 만들어집니다. Class Loader는 JVM이 필요한 클래스의 바이너리 정보를 찾아 읽고, 클래스를 사용할 수 있게 하는 **Loading**에 관여합니다. 이후 JVM은 Linking과 Initialization 과정을 진행합니다.

## 1. 클래스가 준비되는 과정

| 단계 | 주요 역할 |
| --- | --- |
| Loading | 클래스의 바이너리 정보를 찾아 읽고 JVM에 클래스 정보를 생성 |
| Linking | Bytecode 검증, `static` 필드의 기본값 준비, 필요한 참조 연결 |
| Initialization | `static` 필드의 명시적 초기화 코드와 `static` 블록 실행 |

Linking은 자세히 보면 **Verification → Preparation → Resolution**으로 나뉩니다. Resolution의 실제 수행 시점 등은 JVM 구현에 따라 달라질 수 있습니다. **Class Loader가 모든 단계의 코드를 직접 실행하는 것으로 이해하지 말고**, JVM이 클래스를 로딩·링킹·초기화하는 흐름으로 이해하면 됩니다.

## 2. 클래스 초기화와 객체 생성

```java
public class Main {
    static class User {
        static {
            // User 클래스가 초기화될 때 실행된다.
            System.out.println("User 클래스 초기화");
        }

        User() {
            // User 객체를 생성할 때마다 실행된다.
            System.out.println("User 객체 생성");
        }
    }

    public static void main(String[] args) {
        new User();
        new User();
    }
}
```

실행 결과:

```text
User 클래스 초기화
User 객체 생성
User 객체 생성
```

첫 `new User()`에서 **아직 User 클래스가 초기화되지 않았다면**, JVM이 먼저 클래스 초기화를 수행합니다. 그래서 `static` 블록이 한 번 실행됩니다. 이후 `new`가 객체를 위한 메모리를 할당하고 인스턴스 필드를 초기화한 다음 생성자가 실행됩니다. 두 번째 `new User()`에서는 클래스 초기화를 반복하지 않고 새 객체를 만들어 생성자를 다시 실행합니다.

```text
처음 new User() 실행
  → 필요하면 User 클래스 Loading·Linking·Initialization
  → 객체의 메모리 할당과 기본값 설정
  → 인스턴스 초기화·생성자 실행
  → 객체 참조 반환
```

위 순서는 학습용 개념 흐름입니다. 클래스의 Loading·Linking은 첫 `new`보다 앞서 일어날 수도 있고, `static` 메서드 호출이나 `static` 필드 사용 등으로 클래스가 먼저 초기화될 수도 있습니다. 출력으로 확인할 수 있는 것은 **클래스 초기화 시점**이지 Loading의 정확한 시점은 아닙니다.

| 구분 | 클래스 초기화 | 객체 생성 |
| --- | --- | --- |
| 대상 | 클래스의 `static` 초기화 코드 | 각각의 새 인스턴스 |
| 대표 코드 | `static { ... }` | `new User()`, 생성자 |
| 실행 횟수 | 같은 클래스의 해당 초기화는 보통 한 번 | `new`로 만들 때마다 |
| 이전 주제와 연결 | 클래스 수준의 정보와 상태 | Heap의 객체와 이를 가리키는 참조 |

클래스의 초기화 횟수를 말할 때는 **어떤 Class Loader가 정의한 클래스인가**도 고려해야 합니다. 서로 다른 Class Loader가 같은 이름의 클래스를 각각 정의할 수 있습니다.

## 3. 부모 위임

일반적인 Class Loader는 클래스를 찾을 때 먼저 부모 Class Loader에 요청하고, 부모가 찾지 못하면 자신이 찾습니다. 이를 **부모 위임(Parent Delegation)**이라고 합니다. Java 기본 클래스와 애플리케이션 클래스가 적절한 로더에서 로딩되도록 하는 데 도움이 됩니다. 사용자 정의 Class Loader는 목적에 따라 다른 방식을 사용할 수 있습니다.

## 4. 앞에서 배운 메모리와 연결

클래스 정보는 JVM이 클래스의 필드·메서드 등을 이해하는 데 사용됩니다. `new User()`로 생성되는 각 **객체는 개념적으로 Heap에** 놓이고, 메서드의 지역 참조 변수는 해당 **Stack Frame에서 그 객체를 가리킵니다**. 클래스 정보가 준비되는 일과 개별 객체의 생성은 서로 다른 과정입니다.

## 면접 질문

### Q. 클래스 초기화와 객체 생성의 차이는 무엇인가요?

Class Loader는 필요한 클래스의 바이너리 정보를 로딩합니다. JVM은 클래스를 Linking한 뒤 처음으로 초기화가 필요한 시점에 `static` 필드 초기화 코드와 `static` 블록을 실행합니다. `new`로 객체를 만들 때 클래스가 아직 초기화되지 않았다면 이를 먼저 수행하고, 이후 객체에 메모리를 할당해 인스턴스를 초기화하고 생성자를 실행합니다. 같은 클래스로 객체를 여러 개 만들더라도 클래스 초기화는 매번 반복되지 않지만 생성자는 객체마다 실행됩니다.

## 핵심 정리

- Class Loader는 필요한 클래스의 **Loading**에 관여합니다.
- JVM의 클래스 준비 흐름은 **Loading → Linking → Initialization**입니다.
- `static` 블록은 **클래스 초기화** 때 실행됩니다.
- 첫 `new`는 필요하다면 클래스 초기화를 먼저 일으킨 뒤 **객체 생성**으로 이어집니다.
- 새 객체를 만들 때마다 메모리 할당과 인스턴스 초기화·생성자가 실행됩니다.
- 클래스 초기화와 객체 생성의 횟수 및 대상을 구분해야 합니다.
